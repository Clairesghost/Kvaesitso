# Dry run: a made-up user, to prove the interview is complete enough

User: "Robin", wants a cosy forest theme, a two-page Home and a bottom dock. Invented. No art, no brand.

## How the walk-through went
Each group in `docs/question-bank.md` was answered the way Robin plausibly would, in batches of at most four (G1 + G2, G3 + G4, G5 + G6 + G7, G8 + G9, G10 + G11, G12 + G13 + G14, G15). Every answer became a `D-n` line (`decisions.md`). The result had no gaps that stopped a brief from being written:
- Look, palette, fonts: enough to fill `docs/design-system.template.md` (palette roles, fonts, motifs).
- Layout, header, dock, gestures, typing layer, landscape, motion: enough for the briefs.
- Wallpaper, icons, keyboard, selling: recorded, some as LIMIT or SKIPPED.

## Gaps found during the dry run (and fixed in the kit)
1. The bank had no question on page dots or empty states: added as Q4.6, and the guide also asks small details as "open questions" in the preview step of a brief (see brief-3).
2. A user who picks "no hero element" needs the follow-up questions skipped: the guide rule "skip questions already answered or made moot" covers it (D-6).
3. The phone's make and model were needed before any Android advice: PHASE 0 of the guide records them under "Phone" first.

## Files
- `decisions.md`: the filled `ops/decisions.md`.
- `brief-1-T0-build.md`, `brief-2-T1-theme-and-dock.md`, `brief-3-T2-home-pages.md`: the first three briefs, as the guide would write them to `tasks/<id>/brief.md`.

Not proven: that a real stranger would answer this way, or that the builds would succeed (nothing was built).
